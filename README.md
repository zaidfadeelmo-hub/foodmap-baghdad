# FoodMap Baghdad — دليلك لأطيب لقمة ببغداد

منصة ويب عربية (RTL، Mobile First) لاكتشاف المطاعم والكافيهات في بغداد.
**Next.js 15 (App Router) + TypeScript + Supabase (PostgreSQL/Auth/Storage) + Leaflet/OpenStreetMap.**

**وضع العرض التجريبي:** بدون مفاتيح Supabase يعمل الموقع ببيانات محلية (`src/data/demo.json`):
التصفح والبحث والفلاتر والخريطة تعمل، والمفضلة تُحفظ في المتصفح. التسجيل والتقييم والإضافة والإدارة تحتاج Supabase.

## التشغيل المحلي

```bash
npm install
npm run dev          # http://localhost:3000  (وضع تجريبي بدون أي إعداد)
```

## ربط Supabase (حقيقي)

1. أنشئ مشروعاً مجانياً في https://supabase.com
2. من **SQL Editor** شغّل الملفات **بهذا الترتيب**:
   1. `supabase/migrations/20261117000000_init.sql` — الجداول + RLS + Storage
   2. `supabase/seed/reference_data.sql` — بغداد ومناطقها وتصنيفات الأكل (مطلوب للإنتاج)
   3. `supabase/seed/demo_data.sql` — *(اختياري)* مطاعم تجريبية للتجربة فقط
3. من **Project Settings → API** انسخ `Project URL` و `anon public key` إلى `.env.local`
   (انسخ `.env.example`). **لا تستخدم `service_role` أبداً في هذا المشروع.**
4. من **Authentication → URL Configuration** أضف:
   - Site URL: رابط موقعك
   - Redirect URLs: `http://localhost:3000/auth/callback` و `https://دومينك/auth/callback`
5. سجّل حساباً من الموقع، ثم اجعله مديراً (SQL Editor):
   ```sql
   update public.profiles set role = 'admin'
   where id = (select id from auth.users where email = 'بريدك@example.com');
   ```
6. افتح `/admin` لاعتماد الاقتراحات ورفع صور المطاعم الحقيقية.

## البيانات التجريبية والصور — سياسة واضحة

- كل مطعم تجريبي له `is_demo = true` وتظهر عليه شارة **«بيانات تجريبية»**، وأسماؤه وتقييماته وإحداثياته (تقريبية لمركز الحي) **غير حقيقية**.
- الصور المؤقتة رسومات SVG مولَّدة (`public/placeholders`)، وتحمل `is_placeholder = true` وشارة **«صورة تجريبية»**. لا تُنسب أي صورة لمطعم حقيقي.
- صفحات المطاعم التجريبية لا تُفهرس في محركات البحث (`noindex`).
- **قبل الإطلاق:** شغّل `supabase/seed/remove_demo_data.sql` لحذف كل البيانات التجريبية.
- الصور الحقيقية تُرفع فقط من `/admin` (JPG/PNG/WEBP حتى 5MB) وتُخزَّن في bucket `restaurant-images`. الصور الحقيقية تظهر قبل التجريبية تلقائياً.

## التوسع لمحافظات أخرى (بدون إعادة بناء)

- جدول `cities` يحتوي بالفعل على البصرة والموصل وأربيل والنجف وكربلاء والسليمانية وكركوك ودهوك (غير مفعّلة).
- أضف مناطق المدينة في جدول `areas`، ثم `update cities set is_active = true where slug = '...'`.
- يُحدَّد النطاق الحالي بالمتغير `NEXT_PUBLIC_DEFAULT_CITY`. الخطوة التالية للتوسع الكامل: محدد مدن في الواجهة (البنية جاهزة: كل مطعم مرتبط بـ `city_id`).

## البنية

```
src/app/            الصفحات (App Router) + actions.ts (Server Actions)
src/components/     البطاقات، الخريطة، النماذج، التنقل
src/lib/data.ts     طبقة البيانات (Supabase أو وضع تجريبي)
src/lib/supabase/   عميل الخادم
src/middleware.ts   تجديد جلسة Supabase
src/data/demo.json  المصدر الوحيد للبيانات التجريبية
scripts/            مولّد الصور التجريبية ومولّد ملفات seed
supabase/           المخطط والبيانات المرجعية والتجريبية
```

أعد توليد الملفات بعد تعديل `demo.json`: `npm run placeholders && npm run seed:generate`.

## النشر (Vercel — مجاني للبداية)

1. ارفع المشروع إلى GitHub واستورده في https://vercel.com
2. أضف متغيرات البيئة الأربعة من `.env.example` (مع `NEXT_PUBLIC_SITE_URL` = رابط الإنتاج).
3. حدّث Redirect URLs في Supabase برابط الإنتاج.

## ملاحظات مهمة قبل الإطلاق العام

- **بلاطات OpenStreetMap:** الخادم العام `tile.openstreetmap.org` مناسب للتطوير وحركة المرور المنخفضة فقط ([سياسة الاستخدام](https://operations.osmfoundation.org/policies/tiles/)). للإنتاج استخدم مزوّد بلاطات (MapTiler، Stadia، Thunderforest…) وبدّل `OSM_TILES` في `src/components/MapView.tsx`. ما زالت البيانات من OpenStreetMap.
- **البريد:** خدمة البريد الافتراضية في Supabase محدودة جداً. اربط SMTP خاصاً (Resend، SendGrid…) من Authentication → SMTP قبل فتح التسجيل للعامة.
- **الإشراف:** المراجعات تُنشر فوراً. أضف آلية إبلاغ/إشراف قبل التوسع (الإدارة تستطيع حذف أي مراجعة عبر RLS).
- **محتوى حقيقي:** المراجعات «الحقيقية» تأتي من مستخدمين حقيقيين بعد الإطلاق؛ لا تُدخل تقييمات مصطنعة.
- **حالة الفحص:** مخطط قاعدة البيانات وملفات seed وسياسات RLS اختُبرت فعلياً على PostgreSQL 16 (زائر/مستخدم/مدير، ومنع التلاعب بالحالة والدور والتقييمات). أما كود Next.js فلم يُبنَ بعد لعدم توفر `npm install` في بيئة التطوير التي كُتب فيها؛ شغّل `npm install && npm run typecheck && npm run build` كأول فحص، وأصلح أي ملاحظة نوع قد تظهر.
